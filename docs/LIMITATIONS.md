# Known limitations

## Verification status
* **The images are release candidates.** What was checked offline is in `VALIDATION.md`. The **Tianma** image was flashed and booted
  on **one** tablet (2026-11-20): U-Boot → systemd-boot → Plasma Setup (on-screen keyboard works) → account → first-login setup →
  home screen and dock. That is one tablet and one run, reported by the maintainer. The **CSOT** image has no hardware test.
* Not yet checked on hardware: the shutdown/reboot splash, package upgrades (`apk upgrade`), suspend/resume, the camera first-use download,
  *DorothyOS Start* and *DorothyOS Settings* by touch, and anything on CSOT. See `VALIDATION.md` §5.

## Hardware (status of the mainline kernel on this tablet; from the reference tablet and upstream notes)
* Working on the reference tablet: display with hardware-accelerated graphics (OpenGL ES 3.2 / Vulkan 1.3), touch, Wi-Fi,
  Bluetooth, audio (speakers, microphone, headset jack), accelerometer/auto-rotate, ambient light sensor, suspend to idle (s2idle).
* Camera: the **rear** camera (OV13B10, 13 MP) works on the reference tablet through libcamera's software ISP. There is **no front
  camera** and **no autofocus** (neither is described in the mainline device tree), colours are muted (no tuning file for this
  sensor), and only one app may use the camera at a time. The first time you open **Camera** the system offers to download the
  recommended app (Cosmic Camera, ≈ 170 MB, from Flathub) — GNOME Snapshot is installed as a fallback but does not follow the
  screen rotation. Details: `overlay/dorothyos-tablet/src/camera/README.md`.
* Not working / limited (kernel and firmware, not this project): the `bq25980` charge-pump driver reports a probe error (the
  battery can show *Discharging* while on USB, fast charge probably limited); occasional `vblank timeout` kernel messages around
  screen wake-up; a steady "Handover signaled, but it already happened" kernel message about 5 times per second (harmless but a
  wake-up/log write). Stylus, keyboard-cover and fingerprint support were not examined.
* The sensor registry (needed for the accelerometer) is copied **at the first boot from the tablet's own `persist` partition**
  by `pipa-sensors-registry.service`. If `persist` is empty or damaged the sensors do not work and auto-rotate is missing. This path
  is validated only on the reference tablet.

## Software
* Root is **not encrypted** (see `SECURITY-MODEL.md`) and sshd is **off** by default.
* Wallpapers: eight DorothyOS wallpapers (generated by `branding/wallpapers/make-wallpapers.py`, CC0-1.0) rotate every hour
  on the desktop and the lock screen. The author's personal photo collection is **not** part of the project.
* Boot splash: the DorothyOS Plymouth theme (orange ring with a turning arc) was written to mirror the stock postmarketOS theme's API
  and could **not** be rendered offline (no framebuffer in the build container). If the stock splash shows instead, see
  `docs/BRANDING.md` → "Boot splash". The **start menu** (`DorothyOS Start`) and the **Settings** app were rendered offscreen and
  run on the reference tablet, but touch behaviour such as long-press menus was not exercised by a person yet.
* Third-party brand tiles and third-party Flatpaks are not part of the image; the home screen starts with
  free apps only (Okular, Kate, Calculator, Firefox, Files, Gwenview, Camera, Discover, Settings, Terminal, System Monitor, Screenshot).
* Plasma Setup is a new KDE component. On the Tianma tablet it starts, takes touch input and shows the on-screen keyboard (the image
  enables the keyboard system-wide in `/etc/xdg/kwinrc`, because the wizard runs as a throw-away user). Its look (scale, rotation) was
  not examined in detail; the 250 % scale and landscape come from `/etc/xdg/kwinoutputconfig.json`.
* Kernel and device packages are not pinned in the image (the reference tablet pins them). A kernel update that changes the boot
  entry's device tree would be a problem for the wrong panel variant; see `INSTALL.md` → Updating.
* The lock-screen patch is tied to Plasma 6.8 (`lockscreen-patch.py` asserts every text it replaces and falls back to the stock lock
  screen if a Plasma update changed it).
* Build output is not bit-for-bit reproducible (`BUILD.md`).
* Images are large (≈ 4.3 GB sparse each); GitHub release assets are limited to 2 GiB, so they are published compressed/split.

## Next steps (planned, not promised)
* **Better camera quality** — a proper libcamera tuning profile for the rear OV13B10 sensor (colour, white balance, noise), then autofocus and the front camera once the kernel can describe them.
* **Making better use of the device's sensors** — the ambient-light sensor and the accelerometer are already available; next come automatic brightness and smarter orientation handling on top of the working auto-rotate.
* **A more native experience** — fewer scripted workarounds, more of the interface as first-class Plasma components, and touch behaviour (gestures, start menu, Settings, lock screen) that feels like a part of the system rather than an add-on.
